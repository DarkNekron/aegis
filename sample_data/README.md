# AEGIS Sample Data (synthetic)

> **Everything in this folder is synthetic.** The domain is `AEGISLAB.LOCAL`, every object's description reads
> "AEGIS synthetic sample data", and each `ground_truth.json` has `"synthetic": true`. No real organisation,
> person or environment is represented.

The files are generated by `scripts/generate_sample_data.py`, and the output is byte-for-byte deterministic.
A test fails if the committed files drift from the generator.

| Dataset | Contents | Purpose |
|---|---|---|
| `corp-small/` | About 40 objects, hand-designed. 8 attack paths from 6 identities: alternatives, a session path, RBCD, a GPO chain, DCSync holders. Decoys that must **not** produce paths. | Exact ground truth for the path engine, min-cut, choke points and remediation simulation |
| `corp-small-v2/` | The same environment one month later: 2 paths remediated, a team move, a new misconfiguration, one account added and one removed | Historical comparison |
| `corp-medium/` | 3,000 noise users, 375 groups and 750 hosts with dense ACLs, admin rights and sessions that never reach tier-0 by construction. 24 planted chains (templates T1–T8, 1–8 hops) and 12 decoys. | Scale and precision: exactly 33 users may have paths |
| `inventory-example/` | Small CSV and AEGIS-JSON inventory files | Shows the custom import formats ([docs/DATA_FORMATS.md](../docs/DATA_FORMATS.md)) |

Import one with:
```powershell
cd backend
.venv\Scripts\python.exe -m app.cli create-snapshot "Sample: corp-small" --sample
.venv\Scripts\python.exe -m app.cli import 1 ..\sample_data\corp-small\corp-small.zip
```

## Conventions assumed by the ground truth

These conventions are the **specification** the graph and path engines must implement. They are repeated
machine-readably in each `ground_truth.json` under `conventions`.

* **Tier-0 seeds:**
  * the domain object
  * domain controllers
  * Domain Admins (512), Domain Controllers (516), Schema Admins (518), Enterprise Admins (519),
    Key Admins (526), Enterprise Key Admins (527)
  * BUILTIN Administrators (544), Account Operators (548), Server Operators (549), Print Operators (550),
    Backup Operators (551)
  * Administrator (500) and krbtgt (502)
* **DCSync holders are tier-0.** That means holding *both* GetChanges and GetChangesAll on the domain.
* **Transitive members of tier-0 groups are tier-0.** A path ends at the **first** tier-0 object it reaches.
  A path that ends at a Domain Admin *user* is therefore as serious as one that ends at the group.
* **Starting identities** are enabled users and service accounts that are not tier-0 and not placeholders.
* **Traversable relationships:**
  * membership and admin: MemberOf, AdminTo, HasSession
  * ACL rights: GenericAll, GenericWrite, WriteDacl, WriteOwner, Owns, AddMember, AddSelf, ForceChangePassword, AllExtendedRights
  * credential and key rights: AddKeyCredentialLink, ReadLAPSPassword, ReadGMSAPassword, WriteSPN
  * delegation: AllowedToAct, AddAllowedToAct, AllowedToDelegate, WriteAccountRestrictions
  * other: HasSIDHistory, Contains, GPLink, DCSync
* **Not traversed:**
  * CanRDP, CanPSRemote and ExecuteDCOM give user-level logon only. Harvesting credentials from a session needs
    local admin, so they never chain into HasSession.
  * TrustedBy is informational.
  * GetChanges or GetChangesAll alone does not grant DCSync.
  * Unknown relationship types are never traversed.
* **Traversal depends on the target's kind.** For example, AddMember only applies to groups, and GenericWrite on a
  domain is not an escalation step. The full table, with explanations and remediation advice, is
  `backend/app/graph_engine/rules.py`.
* **Conditional** (the path is reported as a *conditional attack path*):
  * HasSession
  * AllowedToAct, AddAllowedToAct, AllowedToDelegate, WriteAccountRestrictions
  * AddKeyCredentialLink, WriteSPN
  * GenericWrite on a user, computer, OU or container
  * GenericAll or AllExtendedRights on a computer A path whose edges are all unconditional is reported
  as a *potential privilege escalation*. AEGIS never reports a path as exploited. That label is reserved for an
  analyst's manual validation.

## How the ground truth is verified
`backend/tests/test_sample_datasets.py` imports every dataset and recomputes the ground truth with a separate,
deliberately simple reference implementation (`backend/tests/reference_paths.py`): breadth-first and depth-first
search over Python sets. The tests check:
* tier-0 membership
* every source's shortest hop count, and which identities have no path
* the complete list of paths and their classifications
* the top choke point
* the minimum cut: it disconnects everything, a witness set of edge-disjoint paths proves no smaller cut exists, and
  it is unique
* both remediation simulations
* every v1→v2 change
* for corp-medium, that exactly the 33 expected users have paths and all 12 decoys stay inert
